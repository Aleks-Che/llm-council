# Поиск перед запуском совета

1. Откройте настройки совета (⚙️).
2. В разделе «Поиск в интернете» добавьте личный ключ [Tavily](https://app.tavily.com) и выберите модель исследования из моделей вашего прокси.
3. Сохраните настройки. В новом диалоге включите «Поиск» слева под полем ввода и отправьте вопрос.

Общий серверный ключ можно задать через `TAVILY_API_KEY` в `.env`; после изменения `.env` перезапустите backend. Личный ключ имеет приоритет. Удаление личного ключа возвращает использование серверного, если он задан. API настроек возвращает только признак наличия ключа. Сам ключ хранится на сервере в персональном `settings.json`, а не в localStorage браузера.

## Что происходит

Модель исследования составляет план и 1–3 поисковых запроса. Backend выполняет Tavily Search (`advanced`, без готового ответа), удаляет повторяющиеся URL и просит модель выбрать источники. Tavily Extract возвращает текст выбранных страниц; неудачные страницы один раз повторно обрабатываются с `advanced` extraction. Недоступные страницы, короткие заглушки проверки браузера и точные повторы текста не считаются прочитанными независимыми источниками.

Из полученного текста выбираются исходные фрагменты с постоянными идентификаторами (`S1E1`). Модель составляет фактическую справку, привязывает её к выдержкам и проверяет покрытие каждого пункта плана. Если остались пробелы, выполняется следующий проход с новыми запросами. Повторяющиеся запросы не выполняются. Решения модели проверяются по JSON-схемам; для некорректного JSON разрешена одна попытка исправления.

Совет, судьи и председатель получают один и тот же пакет: справку, исходные выдержки, URL, даты и ограничения. Backend подставляет URL по реестру источников в ссылки вида `[S1E1]`. Несуществующие идентификаторы помечаются как неподтверждённые. Это проверка идентификаторов; содержательное соответствие утверждения источнику оценивают модели.

## Лимиты и сбои

По умолчанию: 2 прохода, до 6 поисковых запросов, до 10 разных страниц, 180 секунд на всё исследование. Настройки позволяют выбрать 1–3 прохода, 1–6 запросов, 1–12 страниц и 30–300 секунд. Повторные транспортные попытки для временных ошибок и повторное извлечение уже выбранных страниц также ограничены; число фактических API-вызовов может превышать число уникальных запросов и страниц. Показываются использованные кредиты, если Tavily вернул их в ответе.

Контекст исследования ограничен 24 000 символов по умолчанию; параметр `search.context_chars` в API настроек допускает 8 000–48 000. Это лимит символов, не точный подсчёт токенов. Полные тексты не добавляются в каждый запрос совета. Сохраняется до 120 000 символов страницы; сокращение отмечается при просмотре.

Если ключ отсутствует, отправка отклоняется до создания сообщения, вопрос остаётся в поле ввода. При частичных результатах или таймауте совет получает доступные выдержки и список пробелов. Если ничего прочитать не удалось, интерфейс и контекст совета явно сообщают об отсутствии веб-подтверждения. «Остановить» отменяет весь запуск, сохраняя уже полученный прогресс. Перезапуск сервера помечает незавершённое исследование как прерванное.

Настройки фиксируются при запуске; их изменение влияет на следующие запросы. Поиск выключен по умолчанию. Вложения передаются модели исследования вместе с вопросом; поисковику отправляются сформулированные поисковые запросы.

## Просмотр и хранение

В блоке «Поиск и источники» доступны план, запросы, найденные факты, пробелы, статусы источников и выдержки. Кнопка «Показать сохранённый текст» загружает текст отдельно, по запросу пользователя.

Прогресс сохраняется в сообщении разговора в поле `research`. Документы хранятся отдельно: `data/users/{user_id}/research/{conversation_id}-{research_id}.json`. Их API проверяет принадлежность разговора пользователю и наличие источника в сохранённом исследовании. Удаление разговора удаляет его документы.

## Проверки

Из корня проекта:

```bash
python -m unittest backend.test_research -v
```

Из `frontend`:

```bash
npm run build
npm run lint
npm run test:e2e
```

Браузерные тесты используют установленный Google Chrome (или канал из `PLAYWRIGHT_CHANNEL`) и подменяют API синтетическими данными. Проверяются расположение кнопки, передача флага поиска, сохранение вопроса при ошибке, настройки, обновления прогресса, просмотр текста, перезагрузка страницы и остановка запуска. Серверные тесты подменяют Tavily и LLM: реальный ключ и платные вызовы не требуются.
